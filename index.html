05 / A JORNADA NÃO É LINEAR

Aprender fazendo.
E refazer melhor.

Uma trilha de fundamentos até a entrega de um sistema full-stack. Os tópicos abaixo organizam o que já faz parte da prática e o que ainda vale aprofundar — sem confundir estudo em andamento com domínio profissional.

01
A BASE / LÓGICA

Entender o problema antes de escrever a solução

A lógica sustenta todas as camadas: antes de pensar em telas, rotas ou consultas, é preciso transformar um problema grande em passos menores, compreensíveis e testáveis.

Linguagem e raciocínio

  • Variáveis, constantes, tipos de dados, conversões e operadores.
  • Estruturas condicionais, operadores lógicos e decisões com múltiplos cenários.
  • Laços de repetição, listas, vetores e percorrer coleções com segurança.
  • Métodos, parâmetros, retorno e responsabilidade única para cada bloco.

Como praticar de verdade

  • Separar entrada, processamento e saída de um problema.
  • Testar caminho feliz, valores vazios, limites e entradas inesperadas.
  • Ler mensagens de erro, depurar passo a passo e formular hipóteses.
  • Refatorar exercícios para reduzir repetição e melhorar os nomes.
FUNDAMENTOS
02
A WEB / FERRAMENTAS

Construir interfaces acessíveis, responsivas e organizadas

Uma interface bem feita não é só aparência: estrutura, hierarquia visual, acessibilidade e comportamento precisam funcionar em diferentes larguras de tela e formas de interação.

HTML e CSS

  • HTML semântico, títulos em ordem, links, formulários e rótulos claros.
  • Cascata, especificidade, variáveis CSS, tipografia, espaçamento e contraste.
  • Flexbox, Grid e media queries para desktop, tablet e celular.
  • Estados de foco, navegação por teclado e preferência por movimento reduzido.

JavaScript e fluxo de trabalho

  • DOM, eventos, validação de formulários e atualização de conteúdo.
  • Funções, módulos, arrays, objetos, promises e async/await.
  • Git para registrar mudanças pequenas, com commits que expliquem a intenção.
  • GitHub para versionar, documentar, revisar diferenças e manter um README útil.
WEB / GIT
03
FRONT-END / REACT

Transformar telas em componentes reutilizáveis

O front-end organiza a experiência de quem usa o sistema. O objetivo é separar a interface em peças com responsabilidades claras e manter o estado visual coerente com os dados recebidos.

Componentização e estado

  • Componentes funcionais, JSX, props e composição.
  • Estado local, eventos, renderização condicional e listas com identificadores estáveis.
  • Hooks como useState e useEffect, entendendo quando realmente são necessários.
  • Formulários controlados, mensagens de validação e feedback de ação.

Consumo de serviços

  • Requisições HTTP com fetch ou ferramenta equivalente e leitura de JSON.
  • Estados de carregamento, sucesso, ausência de dados e falha.
  • Separação entre componentes visuais, funções de acesso à API e configuração.
  • Conferência em celular: toque, espaçamento, overflow, menu e legibilidade.
FRONT-END
04
BACK-END / C# E .NET

Projetar uma API que tenha contratos claros e regras confiáveis

No back-end, a interface deixa de ser a autoridade sobre os dados. A API recebe requisições, valida entradas, aplica regras de negócio, coordena a persistência e devolve respostas HTTP consistentes. Esta é uma área central para aprofundar na jornada.

Fundamentos da API REST

  • C# com classes, interfaces, encapsulamento, coleções, LINQ e tratamento de exceções.
  • ASP.NET Core, rotas, controllers ou endpoints e separação entre entrada e lógica de negócio.
  • Verbos HTTP com propósito: GET, POST, PUT/PATCH e DELETE.
  • Status codes consistentes, como 200, 201, 204, 400, 401, 403, 404 e 500.
  • DTOs para controlar o que entra e sai, sem expor a entidade de banco diretamente.

Organização, validação e segurança

  • Validar dados no servidor: obrigatoriedade, formatos, limites e relações de negócio.
  • Separar controllers, serviços e acesso a dados conforme a complexidade do projeto.
  • Injeção de dependência, configuração por ambiente e middleware.
  • Tratamento global de erros e logs úteis sem vazar senhas, tokens ou dados pessoais.
  • Swagger/OpenAPI para documentar e testar contratos da API.
  • Estudar autenticação, autorização por perfil, CORS, proteção de segredos e testes.

Ponto de atenção: autenticação, autorização e controles de produção devem ser validados e testados antes de qualquer sistema real. A lista é uma trilha de aprofundamento, não uma declaração de que todos esses itens já estão concluídos.

BACK-END
05
BANCO DE DADOS / PERSISTÊNCIA

Modelar dados pensando nas relações e na integridade

O banco não é apenas um lugar para salvar registros. Uma boa modelagem evita duplicação, preserva relações e torna consultas e alterações previsíveis à medida que o sistema cresce.

Modelagem e SQL

  • Entidades, tabelas, colunas, tipos e regras de nulidade.
  • Chaves primárias e estrangeiras, relacionamentos 1:1, 1:N e N:N.
  • Normalização para reduzir redundância e evitar inconsistências.
  • SELECT, WHERE, ORDER BY, funções de agregação e JOIN.
  • INSERT, UPDATE, DELETE, constraints e transações.

EF Core e responsabilidade

  • Entidades, DbContext, configuração de relacionamentos e migrations.
  • Consultas assíncronas, projeções e atenção a consultas desnecessárias.
  • Índices quando justificáveis e análise de desempenho de consultas.
  • Parâmetros e ferramentas de acesso seguras para reduzir risco de SQL injection.
  • Configurar credenciais fora do repositório e planejar cópias de segurança.
DADOS / MYSQL
06
INTEGRAÇÃO / FULL-STACK

Fazer as camadas conversarem como um único sistema

O ChurchManager é o contexto prático para estudar essa conexão: uma interface React/Vite, uma API em C# / ASP.NET Core e persistência relacional em MySQL. O projeto segue em desenvolvimento acadêmico.

O caminho de uma operação

  • A pessoa preenche uma tela; o front-end valida o básico e envia a requisição.
  • A API verifica o contrato, valida a entrada e aplica regras de negócio.
  • A camada de dados consulta ou altera MySQL usando a persistência configurada.
  • A API devolve status e JSON; a interface transforma o resultado em feedback compreensível.

Testes de integração manual

  • Confirmar URLs, variáveis de ambiente e permissões entre front-end e API.
  • Tratar CORS como configuração explícita, não como solução para qualquer erro.
  • Verificar carregamento, sucesso, erro de rede, resposta vazia e sessão expirada.
  • Testar criação, edição, consulta e exclusão com dados controlados.
  • Documentar o que funciona, o que é parcial e o que ainda precisa de validação.

07
QUALIDADE / PUBLICAÇÃO

Entregar algo que possa ser entendido, mantido e evoluído

Concluir uma funcionalidade não encerra o trabalho: é preciso verificar comportamento, proteger configurações, documentar limites e tornar a aplicação observável depois da publicação.

Confiabilidade

  • Testes unitários para regras isoladas e testes de integração para contratos importantes.
  • Revisão de erros de console, formulários, navegação, teclado e layout em diferentes telas.
  • Acessibilidade: rótulos, foco visível, contraste, semântica e mensagens claras.
  • Logs sem informações sensíveis, validação do lado do servidor e dependências atualizadas.

Entrega e melhoria contínua

  • Branches e commits pequenos para facilitar revisão e reversão de mudanças.
  • README com objetivo, stack, requisitos, execução, arquitetura e limitações.
  • Separar configuração local e produção; nunca versionar chaves ou senhas.
  • Planejar hospedagem do front-end, API e banco persistente de forma compatível.
  • Verificar logs e saúde da aplicação após cada publicação e corrigir regressões.
