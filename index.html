ESTUDO DE CASO / 01

ChurchManager: pensar no sistema inteiro.

TCC · EM EVOLUÇÃO

Um projeto acadêmico para explorar como interface, regras de negócio e dados trabalham juntos em uma aplicação web responsiva para rotinas administrativas de uma comunidade.

01 / CONTEXTO

Organizar informações

Reunir rotinas como membros, ministérios, eventos, escalas e registros financeiros em módulos claros, em vez de espalhar controles por ferramentas diferentes.

02 / ABORDAGEM

Separar responsabilidades

O front-end React/Vite conversa com uma API REST em C# / ASP.NET Core. A API aplica regras e se comunica com o MySQL; o navegador não acessa o banco diretamente.

03 / PRÁTICA TÉCNICA

Construir com limites explícitos

O repositório documenta autenticação, validação, configuração por ambiente e separação por módulos — além do que ainda precisa de homologação antes do uso real.
